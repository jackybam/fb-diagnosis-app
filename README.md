# 상권 진단서 (F&B 창업 진단 프로토타입)

## 지금 상태
- **지역 입력이 자동완성 방식으로 바뀌었습니다.** 시/군/구+동을 따로 텍스트로 치는 대신, 실제 행정동 목록에서 검색·선택하는 방식이라 "동백동"처럼 동백1동/2동/3동으로 갈라진 지역도 정확히 선택 가능합니다.
- 지역을 목록에서 선택하지 않으면 진단 버튼을 눌러도 진행되지 않습니다 (필수 입력 검증).
- **"내 아이디어 검증" 탭의 "동일업종 매장 수"만 실데이터**입니다.
  (소상공인시장진흥공단 상권정보 API로 선택한 행정동의 실제 매장 개수를 가져옵니다)
- 나머지 지표(관심도 지수, 진입 난이도, 프랜차이즈 탭 전체)는 여전히 샘플 로직 기반 추정치입니다.
- 화면에 "추정" / "실데이터" 태그로 구분해뒀습니다.

## 배포 방법 (Vercel)
1. 이 폴더를 깃허브 저장소로 올립니다. (Vercel이 깃허브와 연동해서 자동 배포)
2. https://vercel.com 에서 깃허브 계정으로 가입 → "Add New Project" → 방금 만든 저장소 선택
3. **환경변수 설정** (배포 전에 꼭 필요)
   - Vercel 프로젝트 설정 → Environment Variables
   - Key: `SBIZ_API_KEY`
   - Value: 공공데이터포털에서 발급받은 서비스키 (URL 인코딩 안 된 원본 값)
4. Deploy 버튼 누르면 끝 — `https://프로젝트명.vercel.app` 링크가 생깁니다.

## 배포 후 꼭 확인해야 할 것 (중요)
API 응답의 정확한 필드 구조를 실제로 호출해보지 않고 문서 캡처만으로 짰기 때문에,
아래 확인이 필요할 수 있습니다.

1. **`/api/suggest?q=용인시기흥구동백`** 호출해서 후보 목록(results 배열)이 정상적으로 나오는지 확인
2. 목록에서 하나 선택 후 실제로 뜨는 `adongCd`로 **`/api/diagnose?adongCd=<값>&biz=한식`** 호출해서 `storeCount`가 정상적인 숫자로 나오는지 확인
   - `totalCount` 필드 위치가 다르면: `api/_lib.js`의 `countStoresInDong` 함수에서
     `data?.response?.body?.totalCount` 부분을 실제 응답 구조에 맞게 수정 필요

## 파일 구조
```
/index.html           → 화면 (자동완성 지역 검색 + 실데이터 연동)
/api/suggest.js         → 지역 자동완성 (타이핑 중 후보 목록 반환)
/api/diagnose.js        → 행정동코드+업종 → 실제 매장 개수
/api/_lib.js            → 공통 API 호출 로직
```
